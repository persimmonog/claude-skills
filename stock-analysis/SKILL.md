# 读懂股票 — 全自动基本面分析 Skill

> **⚠️ 核心规则：** 依照 `references/stock_analysis_framework.md` 搭建的股票分析框架完成股票分析。
> 报告的**结构和内容要求**不在本文件中，而在 `references/stock_analysis_framework.md`。
> **你必须先完整阅读框架文件，再开始任何数据采集。框架文件是本 skill 执行的唯一模板依据。**
>
> **市场文件获取指南：** `references/data_sources_by_market.md` 包含各市场（美股/港股/A股）原始公司文件的获取路径。

---

## 工作流程总览

```
Phase 0: 先读框架文件 → 理解9步结构
    ↓
Phase 1: 解析标的 → 建立 <股票名称> 分析文件夹
    ↓
Phase 2: 数据采集
    ├─ 第1层：Longbridge 原生命令（collect_data.sh）← 主力
    ├─ 第2层：申报文件原文（年报/季报/电话会等）
    ├─ 第3层：Longbridge 新闻/社区
    └─ 补充层：WebSearch（仅数据缺失时使用）
    ↓
Phase 3: 按照框架撰写报告 → 保存 report.md + critical_data.md
    ↓
Phase 4: 质量检查 → 确认分析完整性
结束：stock-analysis/<股票名称>/ 包含 report.md + critical_data.md + source_docs/
```

## Phase 0：理解分析框架

阅读 `references/stock_analysis_framework.md` 文件，确认股票分析方法，后续分析严格按照该框架执行。

---

## Phase 1：解析标的

用户输入可能是：

| 输入类型 | 例子 | 处理方式 |
|---------|------|---------|
| **标准代码** | `MNSO.US`、`9896.HK`、`600519.SH`、`300750.SZ` | 直接使用 |
| **英文名** | `MINISO`、`Tencent`、`Nike` | WebSearch 查代码 |
| **中文名** | `名创优品`、`腾讯`、`贵州茅台` | WebSearch 查代码 |
| **模糊描述** | `那个做盲盒的公司` | AskUserQuestion 确认 |

**代码解析方法：**
- 搜索词：`"<公司名> 股票代码"` 或 `"<company name> stock ticker"`
- 多地上市：优先用 Longbridge 支持的、流动性好的那个市场（HK > US > SH/SZ）
- 记录多个代码备用
- 解析失败 → AskUserQuestion 确认

**解析完成后，记录市场类型**（US / HK / SH / SZ），后续文件获取路径依赖这个判断。

### 建立分析文件夹

解析出股票代码后，通过 `longbridge company` 获取公司中文名，再用公司名创建文件夹：

```bash
# 获取公司中文名（Name栏）
longbridge company <CODE>

# 用脚本创建文件夹
bash scripts/setup_dir.sh "<股票名称>"
```

**文件夹结构说明：**
```
stock-analysis/
  └── <股票名称>/                     # 以公司中文名命名（来自 longbridge company）
      ├── report.md                  # 最终分析报告
      ├── critical_data.md           # 关键信息提取表（从各文件提取的结构化数据）
      └── source_docs/               # 一手原始文档（文件名含发布时间YYYYMMDD）
          ├── 年报_20260409.txt        # 美股：SEC EDGAR 10-K全文
          ├── 季报_20260502.txt        # 美股：SEC EDGAR 10-Q全文
          ├── 委托书_20260409.txt      # 美股：SEC EDGAR DEF 14A全文
          ├── 内部人交易.txt          # 美股：Form 4内部人交易
          ├── 电话会纪要.md           # 电话会Q&A
```

## Phase 2：数据采集

### 设计原则

**Longbridge 能直接拿到的数据，一律不用 WebSearch。**
**每一层的数据采集命令，都标注了它服务框架的哪个 Step。** 你在采集时就知道数据用来回答什么。

### 第1层：Longbridge 原生命令（🟢 高可靠）

直接调用 `scripts/collect_data.sh` 即可一键采集所有模块，数据保存在stock-analysis/<名称>/data目录下。各模块与框架步骤的对应关系见下表。

```bash
# 一键采集所有 Longbridge 数据
bash scripts/collect_data.sh <SYMBOL> "stock-analysis/<股票名称>/"
```

**数据-框架映射表：**

| 模块 | 数据 | 服务于框架 |
|------|------|-----------|
| A 行情与价格 | quote、kline | Step 7 估值 |
| B 财务报表 | 利润表(IS)、资产负债表(BS)、现金流量表(CF) | Step 1 生意本质、Step 4 财务质量 |
| C 估值指标 | calc-index、valuation、consensus | Step 7 估值 |
| D 公司治理 | company、executive、shareholder、dividend | Step 1 生意本质、Step 5 股东回报与治理 |
| E 机构评级 | institution-rating、industry-valuation | Step 7 估值 |
| F 内部人交易 | insider-trades（仅美股） | Step 5 治理 |

### 第2层：申报文件原文（🟢 高可靠）

**阅读读取 `references/data_sources_by_market.md`文件，了解文件下载与处理规则，读取完成后再继续以下步骤**

**建追踪文件：**
```bash
cat > "stock-analysis/<名称>/source_docs/.checklist" << 'EOF'
□ 1.年报  □ 2.季报  □ 3.电话会  □ 4.招股书  □ 5.委托书
□ 6.同行年报  □ 7.行业研报  □ 8.股东变动  □ 9.宏观政策
EOF
```

**按照下面的文件清单依次下载和处理文件，每处理一个文件，更新.checklist里对应选项，再进入下一个文件，不可跳过任何一个文件**
**关键：年报和季报均无法获取 → 停止分析**，告知用户无法继续。

| # | 文件 | 优先级 | 说明 |
|---|------|--------|------|
| 1 | 年报 | 🔴 必选 | **中概股（BABA/JD/MNSO 等）用 20-F 而非 10-K** |
| 2 | 季报/中报 | 🔴 必选 |  |
| 3 | 财报电话会 Q&A | 🔵 高 |  |
| 4 | 招股书（上市5年内） | 🔵 高 |  |
| 5 | 委托书/治理报告 | 🟡 中 |  |
| 6 | 同行公司年报 | 🟡 中 |  |
| 7 | 行业研究报告 | 🟡 中 |  |
| 8 | 股东权益变动 | 🟡 中 |  |
| 9 | 宏观与政策 | ⚪ 低 |  |

### 第2.5层：申报文件质量检查
1. **检查 .checklist**：确认各项是否已完成或标注缺失。仍有 `□` 未处理项的，补做后再进入下一层。
2. **检查关键文档是否存在**：确认 `source_docs/` 下是否有年报、季报/中报等关键文档。

### 第3层：Longbridge 新闻/社区（🟡 中等可靠）→ 服务于框架 Step 5/6（治理/宏观）

这部分也由 `collect_data.sh` 涵盖，如需单独执行：

```bash
longbridge news <SYMBOL>     # 最新新闻（标题+摘要）
longbridge topic <SYMBOL>    # 社区讨论（散户情绪、多空观点）
```

## Phase 3：报告生成

### 核心规则

**报告的 9 步结构由 `references/stock_analysis_framework.md` 完整定义。本 skill 不重复框架内容，你的唯一模板依据是那个文件。**

在开始写报告前：

1. **重新读一遍框架文件**，确保理解每一 Step 要回答的核心问题
2. 依照采集到的数据，包括data、source_docs目录下的文件，重点关注critical_data.md摘录的关键信息，整理各 Step 问题答案，每个问题的答案都必须有依据，不可胡编乱造
3. 框架文件中每个 Step 下方的所有问题，**都必须逐一回答**，要求有理有据。回答句式完整，可读性强。

### 报告开头声明

报告开头必须包含一段**数据获取声明**，格式如下：

```
---
## 数据获取声明

| 数据来源 | 状态 | 说明 |
|---------|------|------|
| 财务数据（Longbridge直连） | ✅ 已获取 | FY20XX-FY20XX 三表完整 |
| 年报原文 MD&A | ✅/❌ 已/未获取 | — |
| 招股书行业概述 | ✅/❌ 已/未获取 | — |
| 财报电话会 Q&A | ✅/❌ 已/未获取 | — |
| 大股东权益变动 | ✅/❌ 已/未获取 | — |
| 股权激励细节 | ✅/❌ 已/未获取 | — |
| 行业研报 | ✅/❌ 已/未获取 | — |
---

```

### 特别注意——Step 0 的公司类型判断

框架中有一个公司类型分类表（平台型/品牌消费品/SaaS/硬科技制造/创新药/公用事业/项目制/渠道品牌/资源周期/金融/早期成长/多元控股）。

**这是整个分析的元决策。** 你必须：

1. 从分类表中找出最匹配的类型
2. 如果横跨多个类型，注明主类型 + 次要特征
3. 根据选定的类型，锁定对应的**行业核心 KPI**（非通用指标，而是该行业真正的胜负手）
4. 填写框架要求的行业指标表（核心KPI 2-3个、次要指标、周期位置、合理估值区间）

### Step 3 的特别要求——区分管理层说法和财报验证

竞争优势分析中，必须区分两层次：

```
公司声称的优势（管理层说法）：
  → 来自年报MD&A / 电话会 / 招股书

财务报表的验证（数据交叉检查）：
  → 真正的定价权体现在毛利率
  → 真正的护城河体现在 ROIC
  → 真正的客户粘性体现在复购率
  → 来自 Longbridge 财务数据
```

不要把管理层说的当成事实。**用财报数据交叉验证管理层的每一个核心宣称。**

### 常见分析失误清单（框架文件中有完整版）

- ❌ 把"行业顺风"当成公司护城河
- ❌ 把报告利润直接当核心利润（忽略一次性收益）
- ❌ PE/PB 数字列了但不解释"隐含预期"
- ❌ 只写多头逻辑不写空头逻辑
- ❌ 待验证问题写得太笼统
- ❌ 数字没有来源

### Step 9 持仓管理规则默认不输出

- 默认**不输出** Step 9（持仓管理/买入卖出建议）
- 只有用户明确问"该不该买"、"仓位多少"、"什么时候卖"等持仓相关问题时，才输出 Step 9
- 输出 Step 9 时，末尾**必须附加**以下免责声明：
  ```
  > **免责声明：** 以上持仓管理建议仅基于公开数据的框架分析，不构成投资建议。
  > 投资有风险，决策需谨慎。本报告作者及AI工具不对任何投资损失承担责任。
  ```

**格式规范：**
- 语言：简体中文，关键财务数字保留原始格式
- 金额单位：人民币用 RMB，美元用 $，统一用亿

### 保存报告到本地

报告撰写完成后，保存到分析文件夹：

```bash
Write("stock-analysis/<股票名称>/report.md", "报告完整内容...")
```

如果用户运行的是打印式分析（非交互式），报告内容 **同时输出到终端和文件**。输出到终端时，在报告末尾注明：

```
---
📁 文件已保存到 stock-analysis/<股票名称>/
   ├── report.md              ← 本报告
   └── source_docs/           ← 获取到的原文（美股：SEC EDGAR 10-K全文 / 港股：WebSearch摘要）
```
